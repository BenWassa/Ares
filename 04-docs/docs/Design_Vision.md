# Legacy Design Vision — Superseded

**Status:** Superseded for Ares 2.0.  
**Authoritative direction:** [`Ares_2_Product_Editorial_Design_Brief.md`](Ares_2_Product_Editorial_Design_Brief.md)  
**Baseline evidence:** [`Ares_2_Baseline_Audit.md`](Ares_2_Baseline_Audit.md)

This file previously served as the comprehensive visual and interaction specification for the current Ares implementation. It fixed the Merriweather/Open Sans pairing, steel-blue/olive/gold palette, repeated tinted surfaces, breakpoint behavior, sidebar/hamburger navigation and other implementation-specific choices.

Issue #4 demonstrated that several of those choices should not remain authoritative for Ares 2.0: ordinary laptop widths lose long-document orientation, complex diagrams are compressed rather than recomposed on phones, some current colour combinations miss the stated accessibility target, and repeated rounded/tinted surfaces weaken the publication's editorial hierarchy.

Issue #5 therefore replaces the old specification with an evidence-led product/editorial direction rather than maintaining two competing design visions. The Git history preserves this document's previous contents for reference; new work under #7–#13 must follow the Ares 2.0 brief instead.

Do not treat the former tokens, fonts, breakpoints, card treatments, gradients, shadows or component prescriptions as Ares 2.0 requirements unless a later implementation issue deliberately re-evaluates and adopts them under the new brief.
